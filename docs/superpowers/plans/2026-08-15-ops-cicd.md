# Production Ops & CI/CD Implementation Plan — Sub-project C

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Containerize the Next.js app (standalone output) and Piper sidecar, add a production compose stack (app + Piper + Postgres + Caddy reverse-proxy) for Portainer on an ASUSTOR NAS, and add GitHub Actions CI/CD (verify → e2e → ghcr.io push → Portainer webhook), plus Node 22 + exact dependency pinning.

**Architecture:** A multi-stage `Dockerfile` builds `.next/standalone` on Node 22-alpine with a fail-fast config check at boot (`/api/health` liveness probe, `scripts/validate-config.mjs` entrypoint gate). `docker-compose.prod.yml` runs four services on two networks (`internal` for app/piper/postgres, `proxy` for app/caddy) — only Caddy publishes ports and terminates TLS. GitHub Actions runs a full gate (lint, tsc, vitest, build, Playwright against a compose Postgres+Piper) then builds and pushes images to ghcr.io and triggers a Portainer stack webhook on `main`.

**Tech Stack:** Docker (multi-stage build, compose v2), Next.js 15 standalone output, Node 22 LTS, Caddy 2, postgres:16-alpine, Piper TTS sidecar (piper-tts 1.6.1), GitHub Actions (setup-node, buildx, login-action, build-push-action).

## Global Constraints

- Node 22 LTS only (`.nvmrc` = `22`; `"engines": { "node": ">=22" }`).
- All dependency versions exact-pinned (no `^`/`~`) matching `package-lock.json`.
- Production config must fail fast: `TRUST_PROXY=true` is required when `NODE_ENV=production` (src/lib/config.ts already enforces via zod `superRefine`).
- `npm run build` and `next dev` without a DATABASE_URL must keep working (build/dev skip DB wiring).
- The container entrypoint runs `scripts/validate-config.mjs` before starting the server.
- `/api/health` must return `200 { "status": "ok" }` without auth (already in middleware `PUBLIC_AUTH`).
- Only Caddy publishes ports in the prod stack; Postgres and Piper are internal-only.
- No Next/React major upgrades; no dependency audit fixes (`npm audit` is advisory + non-blocking in CI).
- Migrations run at app boot via `src/instrumentation.ts` (unchanged behavior when config is valid).
- Never commit secrets: `.env`, `.env.local`, `.env.prod` stay gitignored.
- All gates must stay green after every task: `npx tsc --noEmit`, `npm test`, `npm run build`, `npm run test:e2e`.

Replace the body of `src/instrumentation.ts` `register()`:

```ts
export async function register() {
  if (process.env.NEXT_RUNTIME !== "nodejs") return;
  const { validateConfig, ConfigError } = await import("@/lib/config");
  const config = validateConfig();
  if (!config.ok) {
    // `next build` sets NODE_ENV=production but runs without a DB; skip there.
    // At runtime, an invalid config must crash the container so `docker compose
    // up` fails fast with a useful message instead of serving a broken app.
    if (process.env.NODE_ENV === "production" && process.env.NEXT_PHASE !== "phase-production-build") {
      throw new ConfigError(`Invalid configuration. Missing or invalid: ${config.errors.join(", ")}`);
    }
    return; // no DB configured — build/dev without a DB must still work
  }
  const { runMigrations } = await import("@/lib/db/migrate");
  await runMigrations();
  const { seedAdminIfNeeded } = await import("@/lib/repo/users");
  const { getDb } = await import("@/lib/db");
  await seedAdminIfNeeded(getDb());
}
```

- [ ] **Step 10: Create `scripts/validate-config.mjs`**

```js
#!/usr/bin/env node
// Critical-env check for CI and the container entrypoint. Intentionally
// mirrors src/lib/config.ts without importing it (no TS step in the image).
const failures = [];
const env = process.env;

if (!env.DATABASE_URL) failures.push("DATABASE_URL is required");
else if (!/^postgres(ql)?:\/\//.test(env.DATABASE_URL))
  failures.push("DATABASE_URL must be a postgres:// (or postgresql://) URL");

if (!env.JWT_SECRET || env.JWT_SECRET.length < 32)
  failures.push("JWT_SECRET must be set and at least 32 characters");

if (env.NODE_ENV === "production" && !["true", "1", "yes"].includes((env.TRUST_PROXY || "").toLowerCase()))
  failures.push("TRUST_PROXY must be true in production (rate limiting trusts X-Forwarded-For)");

if (failures.length > 0) {
  console.error("Invalid configuration:");
  for (const f of failures) console.error(`  - ${f}`);
  process.exit(1);
}
console.log("Configuration OK");
```

- [ ] **Step 3: Create the multi-stage `Dockerfile`**

```dockerfile
# ---------- deps ----------
FROM node:22-alpine AS deps
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci

# ---------- builder ----------
FROM node:22-alpine AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN npm run build

# ---------- runner ----------
FROM node:22-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
ENV PORT=3000
ENV HOSTNAME=0.0.0.0
COPY --from=builder /app/.next/standalone ./
COPY --from=builder /app/.next/static ./.next/static
COPY --from=builder /app/public ./public
COPY scripts/validate-config.mjs ./scripts/validate-config.mjs
EXPOSE 3000
HEALTHCHECK --interval=30s --timeout=5s --start-period=15s --retries=3 \
  CMD wget -qO- http://127.0.0.1:3000/api/health >/dev/null 2>&1 || exit 1
ENTRYPOINT ["sh", "-c", "node scripts/validate-config.mjs && exec node server.js"]
```

## Architecture

`docker-compose.prod.yml` runs four services: `app` (Next.js standalone),

### Task 5: GitHub Actions CI/CD

**Files:**
- Create: `.github/workflows/ci.yml`
- Modify: `.env.example` (add the CI secrets comment)

**Interfaces:**
- Consumes: Task 1 pins (`.nvmrc`), Tasks 2–3 Dockerfile + validate-config, Task 4 compose.
- Produces: workflow with three jobs — `verify`, `e2e`, `deploy` (deploy gated to `main` pushes). Image tags: `ghcr.io/${{ github.repository }}/kak-app:{main,<sha>}` and same for `kak-piper`. Requires GitHub secrets `PORTAINER_WEBHOOK_URL` (and optionally `PORTAINER_WEBHOOK_TOKEN`).

- [ ] **Step 1: Write the workflow**

Create `.github/workflows/ci.yml`:

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:

permissions:
  contents: read

jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version-file: .nvmrc
          cache: npm
      - run: npm ci
      - run: npm run lint
      - run: npx tsc --noEmit
      - run: npm test
      - name: npm audit (advisory, non-blocking)
        run: npm audit || true
      - run: npm run build

  e2e:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version-file: .nvmrc
          cache: npm
      - run: npm ci
      - name: Start Postgres + Piper
        run: docker compose -f docker-compose.dev.yml up -d --build
      - name: Run e2e
        run: npm run test:e2e
        env:
          DATABASE_URL: postgres://kak:kak@localhost:5432/kak
          JWT_SECRET: ci-e2e-secret-at-least-32-characters-long
          AUTH_RATE_LIMIT_MAX: "1000"
          PIPER_URL: http://localhost:5001
          TTS_CACHE_DIR: /tmp/kak-tts-cache
          ADMIN_EMAIL: admin@example.com
          ADMIN_PASSWORD: change-me-123
      - name: Teardown
        if: always()
        run: docker compose -f docker-compose.dev.yml down -v

  deploy:
    runs-on: ubuntu-latest
    needs: [verify, e2e]
    if: github.ref == 'refs/heads/main' && github.event_name == 'push'
    permissions:
      contents: read
      packages: write
    steps:
      - uses: actions/checkout@v4
      - name: Set up QEMU
        uses: docker/setup-qemu-action@v3
      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3
      - name: Login to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      - name: Build and push app
        uses: docker/build-push-action@v6
        with:
          context: .
          push: true
          tags: |
            ghcr.io/${{ github.repository }}/kak-app:main
            ghcr.io/${{ github.repository }}/kak-app:${{ github.sha }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
      - name: Build and push piper
        uses: docker/build-push-action@v6
        with:
          context: ./piper
          push: true
          tags: |
            ghcr.io/${{ github.repository }}/kak-piper:main
            ghcr.io/${{ github.repository }}/kak-piper:${{ github.sha }}
          cache-from: type=gha
          cache-to: type=gha,mode=max
      - name: Trigger Portainer redeploy
        run: |
          url="${{ secrets.PORTAINER_WEBHOOK_URL }}"
          if [ -z "$url" ]; then echo "::warning::PORTAINER_WEBHOOK_URL not set; images pushed but stack not redeployed."; exit 0; fi
          curl -fsS -X POST "$url"
```
